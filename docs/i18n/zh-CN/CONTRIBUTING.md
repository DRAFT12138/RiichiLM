# 参与 RiichiLM

欢迎改进模型、强化学习、规则、浏览器牌桌、测试和翻译。先阅读 [README](README.md) 与[路线图](ROADMAP.md)。算法、协议、依赖或架构的大改动，请先通过 issue 讨论再投入实现。

## Issue 与 PR

1. 说明具体问题、预期行为及最小复现，附完整命令、Python／Node／依赖版本、系统／设备和脱敏诊断。规则问题优先使用最小手写局面。
2. 聚焦目标，保持规则校验、数据契约、模型学习和优化器更新的职责边界。Tokenizer 仅编解码，不另造规则引擎；Actor 不得接收对手私有观测。
3. 保留冻结协议标识、词表资源、随机种子域及历史测试样例。变更 checkpoint 或数据格式前，说明兼容性影响。
4. 按变更运行相关检查，报告命令、结果、平台、跳过项及未验证范围，优先使用确定性合成输入。性能结论需在相同模型、精度、上下文、监督量与工作负载下配对测量。
5. 同步更新受影响的英文、中文、日文 README、路线图、贡献说明及界面文案；三语技术结论保持一致，不在翻译中漏掉前提。
6. PR 标题与说明使用英语，写清问题、修改后的行为和验证结果。优先小而可审查的补丁；依赖升级应另行说明。

## 本地检查

按 README 使用 Python 3.14 及一种依赖环境；Web 开发使用 Node.js 20.19+ 或 22.12+。检查示例：

```bash
.venv/bin/python -m pytest tests/unit/tokenizer -q
(cd web && npm ci && npm run build && npm run test:e2e)
```

浏览器测试需有 Playwright 可用的 Chromium，可用 `CHROMIUM_EXECUTABLE` 指定现有安装。涉及模型、规则或 RL 时，运行对应检查。CPU 测试不代表 GPU 结果，短合成实验不代表棋力评估。不因小改动验证而启动全量数据处理或持续训练。

## 不应提交的内容

- 训练／评测数据集、真实或私有牌谱、训练模型、Actor 快照、优化器状态、轨迹和运行产物；测试优先在运行时生成小型合成输入。
- API 密钥、凭据、`.env`、个人路径、缓存、虚拟环境，以及与有意分发变更无关的构建产物。
- 私有具体来源处理、内部 Agent 指令、仓库 skill、项目记忆、内部设计／评审记录及私有验收归档。
- 用于作弊、实时对局辅助或未经授权访问在线服务的功能。

公开 issue、PR、CI 日志及 Release 都不应附带私有数据或权重，发布诊断前先脱敏。本项目不征集数据集或训练权重贡献。项目预训练权重即将开源，下载地址及权重许可将在 README 公布。
