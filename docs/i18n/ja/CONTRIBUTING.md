# RiichiLM への貢献

モデル、強化学習、ルール、ブラウザー対局、テスト、翻訳への貢献を歓迎します。[README](README.md) と[ロードマップ](ROADMAP.md)を確認してください。アルゴリズム・プロトコル・依存関係・構造の大きな変更は、実装に着手する前に issue で相談してください。

## Issue と PR

1. 具体的な問題、期待する挙動、最小の再現手順を示してください。実行コマンド、Python／Node／依存関係のバージョン、OS／デバイス、機密情報を除いた診断を添えてください。ルールの問題には小さな手書き局面を使ってください。
2. 変更は目的に絞り、ルール検証、データ契約、モデルの学習、optimizer 更新の責務を保ってください。Tokenizer は符号化・復号に徹し、別のルールエンジンを持たせません。Actor に相手の非公開観測を渡してはいけません。
3. 凍結済みのプロトコル識別子、Tokenizer リソース、乱数 seed の領域、過去のテスト fixture を保持してください。checkpoint やデータ形式を変更する場合は互換性への影響を説明してください。
4. 変更に応じた検証を行い、コマンド、結果、プラットフォーム、スキップ、未検証範囲を報告してください。可能なら決定的な合成入力を使い、速度比較は同じモデル・精度・文脈・教師情報・負荷で対にして測定してください。
5. 影響する英語・中国語・日本語の README、ロードマップ、貢献説明、UI 文言を同時に更新してください。技術的な内容をそろえ、翻訳で前提条件を省略しないでください。
6. PR のタイトルと説明は英語で、問題、変更後の動作、検証を記載してください。小さくレビューしやすい差分を優先し、依存更新は理由を分けて説明してください。

## ローカル検証

README に従い Python 3.14 と一つの依存構成を使います。Web 開発には Node.js 20.19+ または 22.12+ が必要です。範囲を絞った検証例：

```bash
.venv/bin/python -m pytest tests/unit/tokenizer -q
(cd web && npm ci && npm run build && npm run test:e2e)
```

ブラウザーテストには Playwright で使える Chromium が必要で、`CHROMIUM_EXECUTABLE` で既存の実行ファイルを指定できます。モデル・ルール・RL の変更には対応する検証も実行してください。CPU の結果は GPU 検証ではなく、短い合成実験は強さの評価ではありません。小さな変更の確認だけのために全量データ処理や継続学習を起動しないでください。

## 提出しないもの

- 学習・評価データセット、実牌譜や非公開牌譜、学習済みモデル、Actor スナップショット、optimizer 状態、軌跡、実行出力。小さな合成入力をテスト実行時に生成してください。
- API キー、認証情報、`.env`、個人パス、キャッシュ、仮想環境、意図した配布変更と無関係なビルド出力。
- 非公開のソース固有データ処理、内部 Agent 指示、リポジトリ skill、プロジェクト記憶、内部設計・レビュー、非公開検証アーカイブ。
- 不正行為、リアルタイム対局支援、オンラインサービスへの無断接続を目的とする機能。

公開 issue、PR、CI ログ、Release に非公開データや重みを添付しないでください。診断は投稿前に機密情報を除いてください。データセットや学習済み重みの貢献は募集しません。プロジェクトの事前学習済み重みは近日公開予定で、ダウンロード先とライセンスを README で案内します。
