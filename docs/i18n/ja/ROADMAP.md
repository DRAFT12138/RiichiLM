# ロードマップ

RiichiLM の公開向け計画を新しい基準から始めます。非公開実験や過去の学習日程ではなく、利用者向けの機能と検証可能な次の課題を示します。優先順位は変更される場合があり、公開日や強さの水準は約束しません。

## 実装済みの機能

- [x] 麻雀 Tokenizer、合法行動 trie、Qwen3 ベースの方策、Rust ルールエンジン。
- [x] 行動 token の教師あり学習、共有文脈学習、checkpoint 復帰。
- [x] 自己対戦収集、Oracle Critic、KL 制御付き PPO、凍結対戦相手プール、RL ラウンド境界復帰。
- [x] ローカル対局と四 AI 観戦。各席で NTP・外部 LLM・ランダム戦略を選択。
- [x] 英語・中国語・日本語の画面とプロジェクト文書。

チェック済みは実装の存在を示します。競技的な強さや長期学習の品質は別の評価課題です。

## 1. 再現可能な公開版

- [x] モデル、学習インターフェース、RL、汎用ランタイム／データ部品、Web、必要なテストとリソースのファイル単位の許可リストを確定する。
- [x] 公開 CLI・設定・依存参照を自己完結させる。現在の何切る評価入力を独立設定可能にし、非配布の評価セットを暗黙の前提にしない。
- [x] 自前コーパスの形式と checkpoint の条件を三言語の README に記載する。ソース固有の解析・処理は非公開のままにする。
- [x] エクスポートしたツリーだけでインストールと実質的な回帰検証を行う。既存の依存環境を利用しても非公開ソースは import しない。モデル構築、ランダム Actor の保存・読込、完全対局収集、PPO 更新、保存、新プロセスでの復帰を検証する。
- [x] 独立した Git 履歴の公開リポジトリと公開 CI を作成する。
- [x] 非公開側に手動同期スクリプトを用意する。プレビュー、管理ファイルの明示、競合処理、再現可能な出力を備え、自動同期や強制 push は行わない。

ホストされたCIの実行とCUDA実行検証は、完了したローカルCPU・ブラウザー検証と分けて扱います。

## 2. 実験体験の改善

- [ ] 勾配、活性値、実際のパラメーター更新、KL、エントロピー、Critic／優位度の健全性指標を追加し、観測コストを測る。
- [ ] 貢献者が用意した入力と再現可能な合成例で、共有文脈の長期スループットと数値挙動を評価する。
- [ ] CUDA の独立インストール・実行とネイティブビルドを検証し、プラットフォーム別の証拠を明示する。
- [ ] 実モデルの Web 遅延・メモリを測定する。読込検証や可視情報の境界を弱めずに、卓での RL Actor 対応を検討する。
- [ ] 三言語の用語、アクセシビリティ、狭い画面のレイアウトを改善する。

## 3. 研究と評価

- [ ] Oracle／PPO／KL の比較実験と長期自己対戦を行う。
- [ ] 継続実行で凍結プールの入替、候補昇格、品質ゲートを評価する。
- [ ] 席を入れ替えた比較、不確実性、計算コスト、再現可能な評価手順を報告する。動作確認や loss 曲線だけで強さを推測しない。

## 配布の境界

学習・研究用です。学習データ、評価データセット、事前学習済みモデル、学習済み checkpoint、非公開牌譜は配布しません。互換入力は利用者が用意します。公開文書は README・ROADMAP・CONTRIBUTING の英中日版と、必要なライセンス・帰属情報・参照画像に限定します。リポジトリの skill、AGENTS.md、内部設計、プロジェクト記憶、検証証拠、アーカイブ、非公開処理コード、秘密情報、非公開 Git 履歴はエクスポートしません。
